# AI 연속 토론 규칙

사용자 최신 지시: 회차 제한을 정하지 말고 토론을 계속한다. 한 시간마다 합의점과 이견을 문서로 보고하고, 회차별로 구분하여 Claude와 공유한다.

## 진행
- 참가자는 Claude와 ChatGPT이며 사용자에게 매번 차례 전달을 요청하지 않는다.
- 회차는 발언 식별 번호일 뿐 종료 조건이 아니다. 의견이 모여도 미정 세부 규칙·반례·검증 설계로 논의를 이어간다.
- 기존 6회차 종료 규정과 합의 후 사용자 차례로 넘기는 규정은 폐지한다.
- 사용자 중지 또는 인증·사용량·응답 오류 등 실제 장애가 있을 때 멈추고 사유를 기록한다.
- 동일 주장 반복 대신 새로운 구체 규칙, 반례, 필요한 자료 확인 절차를 제시한다. 근거가 없는 수치는 연구 가설로 표시한다.
- 기존 1차 합의는 보존한다. B·C 전략의 구체 규칙부터 토론하고 A와 공정한 비교 조건으로 이어간다.

## 기록과 공유
- AI는 전달 문서만 읽고 구조화 답변을 반환한다. 파일은 진행기만 쓴다.
- 토론.md에는 차례·안건 표·발언 이력을 남긴다. 각 발언은 회차별 폴더에도 별도 저장한다.
- 합의 표는 상대가 같은 명세를 명시적으로 수용했을 때 합의로 갱신한다. 일방 제안은 합의가 아니다.
- 진행기는 시작 현황 문서를 만들고 시작 시각부터 매1시간마다 시간별보고서 폴더에 번호를 붙여 HTML 및 Markdown 보고서를 저장한다.
- 보고서는 이번 구간의 변경, 현재 합의점, 남은 이견·미정값, 회차별 발언, 공유 내역을 담는다.
- 새 보고서 본문은 각 AI의 다음 요청에 포함한다. AI는 '공유 확인: 정확한 보고서 파일명'을 답변에 적는다.
- 요청에 포함한 기록과 답변에서 공유를 확인한 기록을 구분한다. 작성만 한 것을 공유 완료라고 표시하지 않는다.
- PC가 꺼지거나 절전이면 프로그램은 동작할 수 없다. 재개 시 밀린 구간은 하나의 보고서로 정리한다.
- 이 채팅에 예약 메시지를 전송하지 않는다. 토론장 창 알림과 저장 문서로 사용자에게 알린다.

## 범위
- 이번은 개발 방향과 검증 명세의 토론이다. 거래 프로그램 코드·설정·장부 수정, 주문, 계좌·API키 접근은 하지 않는다.
- 도구가 없는 AI는 실제 데이터를 새로 검사하거나 실험했다고 주장하지 않는다. 필요한 검사를 정확히 명시한다.
- API키 환경변수를 자식에게 전달하지 않고 기존 로그인으로 호출한다. 추가 결제·API 방식 자동 전환은 하지 않는다.
- 한 호출10분 제한, 순차 실행, 내용 해시 검사, 중복 실행 잠금, 중지 버튼을 유지한다. 호출 제한시간은 전체 토론 종료 제한이 아니다.
- 미정 기술값은 두 AI가 검증용 기본안을 제안하고 검토한다. 같은 질문을 반복하여 사용자에게 넘기며 토론을 종료하지 않는다.

## 최우선 목표 변경
현재 업비트 계좌의 모든 보유자산을 포함해 운용을 이어갈 수익 구조와 전환 권고안을 만드는 것이 토론 목적이다. 상세 지시는 운용목표.md를 따른다. 매번 사용자에게 기술 결정을 요구하지 않고 두 AI가 대안·반례를 검토해 권고한다. 기존 평가 도구 안건은 이를 위한 보조 수단이다.
진행기가 기존 로컬 프로그램의 GET 캐시로 확인한 계좌현황_읽기전용.json을 양쪽 AI에 전달할 수 있다. 이 자료는 조회 시각이 있는 관측 자료이며 현재 주문 가능 가격이나 미래 수익 증거가 아니다. AI의 직접 계좌 접근과 주문은 계속 금지한다.

## 사용량 소진 시 자동 대기와 재개 최신 사용자 지시
- 명시적인 구독 사용량 소진이면 전체 토론을 일시 대기한다. 현재 차례와 회차를 보존한다.
- 감지 시각부터5시간 후 같은 AI의 같은 차례를 자동으로 다시 호출한다. 아직 소진 상태이면 다시5시간 대기한다.
- 이것은 재시도 간격이며 공급자의 실제 충전 시각을 보장한다는 뜻이 아니다.
- 대기 중에도 시간별 보고와 단일 현황 문서 갱신을 계속하고 재시도 예정 시각을 KST로 표시한다.
- API키 결제, 추가 사용량 구매, 다른 계정·모델로의 자동 우회는 하지 않는다.
- 수동 중지는 자동 재개보다 우선한다. 인증·문서 오류를 사용량 소진으로 오인하지 않는다.
- 첫 반영 응답에서 '사용량 대기 규칙 확인: 5시간 후 자동 재개'를 적어 공유 확인 기록에 남긴다. 이 운영 규칙 확인 뒤 투자 토론을 계속한다.

## 사용자 최신 역할 변경 지시
ChatGPT 잔여 사용량이4% 미만이므로 Claude가 V5 봇 작성의 주담당이다. 기존 Claude 개발 채팅에서 D:\자동거래 v5 작업을 계속한다. 중복 봇 개발자를 실행하지 않는다. ChatGPT 모델 자동 호출은5시간 유예하고 회복 여부를 재확인한다. 그동안 기록·시간별 보고·Claude 단독 검토와 수정 제안을 계속한다. Claude 혼자 제안한 사항을 ChatGPT가 동의했다거나 두 AI가 합의했다고 표시하지 않는다. 기존 실거래 프로그램과 주문은 변경하지 않는다.


## 사용자 최신 지시 (2026-11-02 21:00, 이 PC) — 앞선 '역할 변경 지시'를 대체한다
- 앞의 '최우선 목표 변경' 아래 '사용자 최신 역할 변경 지시'(ChatGPT 사용량 4% 미만·호출 유예·Claude 주담당)는 회사 PC 당시 상황이며 폐기한다. 현재 ChatGPT는 정상 호출되고 있으므로 일시정지 상태가 아니다. 두 AI는 동등한 토론 참가자다.
- 합의는 한쪽이 제안한 같은 명세를 상대가 명시적으로 수용했을 때 표에 '합의'로 기록한다. 단독 제안은 '제안', 입장이 갈리면 '이견'으로 남긴다. 한쪽이 대행한 단독 검토만 합의로 올리지 않는 원칙은 그대로다.
- 한쪽 사용량이 실제로 소진되면(명시적 사용량 소진 메시지) 사용량이 남은 쪽이 대행해 토론·감시·봇 수정 검토를 계속한다. 이 대행 권한은 계속 유지한다. 대행 기간의 결정은 '단독(대행)'으로 표시하고, 복귀한 상대가 수용하면 합의로 바꾼다. 둘 다 불가하면 5시간 대기 후 자동 재개한다. 유료 API 전환은 하지 않는다.
- 목표는 비용·위험을 반영한 순수익률 개선이다. 수익률 극대화를 위해 이미 본 기간에 맞춘 임계값을 쓰지 않는다. 개선은 신규 기간·그림자(shadow) 모의에서 거래 수, 평균 순손익, 최대낙폭, MAE·MFE로 확인된 뒤에만 개선으로 부른다.
- 합의된 항목의 반영: 합의 표에서 '합의'가 된 코드 변경 명세는 개발 담당(Claude 개발 세션)이 단위 테스트와 함께 모의·그림자 경로에 즉시 반영하고, 변경 내용·커밋·테스트 결과를 토론 문서에 기록한다. 반영 후 ChatGPT가 검토한다.
- 실거래에 영향을 주는 변경(주문·청산 로직, 매도 권한 범위, 금액 한도, 손실 중단선, 위임 범위)은 합의만으로 활성화하지 않는다. 코드는 준비하되 사용자의 명시적 승인 뒤에 켠다. 기본값은 꺼짐이다.

## 사용자 사전 승인 (2026-11-02 23:00) — ChatGPT도 반드시 읽을 것
사용자 원문: "합의 후 합의가 되면 사전 승인을 해줄게. 묻지 말고 적용해. 챗지피티와도 이 내용 공유해."
이것은 두 AI의 '합의'가 실제 실거래 봇의 코드·설정 변경으로 **자동 이어진다**는 뜻이다. 따라서 합의 표시는 전보다 훨씬 무겁다.
- **자동 적용 조건**: 합의 표에서 상태가 `합의`이고 내용에 배포 표지 `[배포:D-xx]`가 들어 있는 줄. 상대가 같은 버전을 명시 수용했을 때만 합의가 되므로, 수용 전에 반례·약한 고리를 모두 제기하라. 표지는 제안자가 넣고 수용자는 같은 표지를 유지한다.
- **적용 대상은 사람이 미리 등록한 목록(`tools/deploy_manifest.json`)**: 현재 D-12(과열 추격 방지·손절 상한 8%·인수 보유분 손절 재설정), D-05(EXIT-T1 실거래), D-22(인수 보유분 1R부터 추적). 목록에 없는 표지는 적용되지 않는다.
- **자동 적용 범위 밖(별도 사용자 지시 필요)**: 주문 금액 한도 상향, 손실 중단선 완화, 실거래 켜기/끄기, 계좌 인수 범위 확대. 게이트가 이 설정 키를 막는다.
- **적용 절차**: 테스트 통과 → 미확정 주문 없음 확인 → 봇 정상 종료 요청 → 백업 → 코드·허용 설정 적용 → 재시작 → 상태 확인 → 실패 시 롤백. 같은 표지는 한 번만 적용.
- **Claude 단독 제안은 합의가 아니다**(변함 없음). 한도 대행 중의 단독 결정은 적용되지 않는다.
- ChatGPT가 반대·유보하면 이견으로 표시하라. 이견은 적용되지 않는다.

## 사용자 권한 공동 부여 (2026-11-02 23:15) — ChatGPT도 반드시 읽을 것
사용자 원문: "지금까지 풀어준 모든 권한을 챗지피티에게도 부여한다."
Claude가 받은 권한(합의 후 자동 적용, 잠정 적용, 배포 명령 실행, 사용자가 명시한 실거래 한도 변경, 이익 보호 적용, 종목·금액 공개, 저장소 커밋 등)을 ChatGPT도 **동일하게** 갖는다. 전체 목록·조건·제외는 `docs/ai-history/permissions.md`. 핵심 한계: 실거래 켜기/끄기·계좌 인수 범위·비밀값은 사용자 명시 지시 없이 다루지 않는다. 토론 세션의 ChatGPT는 파일을 직접 쓰지 못하므로 이 권한은 합의 → 합의 게이트 적용으로 행사한다.
