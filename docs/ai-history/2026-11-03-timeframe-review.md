# 5분봉 판단·30분 교체 주문 전환 평가

기록: 2026-11-03 11:47 KST. 사용자 요청에 따라 실제 Claude CLI 응답을 두 차례 받아 검토·정정했다. 이번 요청은 평가이므로 봇 코드·설정·실주문·실거래 배포는 변경하지 않았다. 수익성 백테스트를 완료한 보고서가 아니다.

## 공동 결론

> 즉시 tf5/주문안 30분을 기각하지 않는다. 다만 실거래 설정(tf15·L72·주문안 60분)은 유지한다. 먼저 15m/60m(현행)과 15m/30m를 비교해 주문 주기만의 효과를 분리한다. tf5를 시험할 때는 18h 보존안(L216 상당. 15분 순위와 5분 진입을 분리하거나 페이지 조회로 217봉 이상 확보)과 6h 변경안(L72)을 별도 모델로 비교한다. 각 비교안은 자기에게 명시된 60분 또는 30분 스케줄대로 실거래형 경로를 모사하고, 비용·노출·초기 보유·stop_tf=240 손절·기존 포지션 ATR 보존 조건을 동일하게 맞춘다. 비용은 설정 가정을 쓰되 실제 호가와 수수료로 재측정한다. 합격 판단은 기간만으로 하지 않고, 서로 다른 장세와 충분한 독립 거래 표본을 근거로 한다. 이번에는 평가만 수행하며 봇 코드·설정·실주문을 변경하지 않는다. 향후 사용자 요청마다 실제로 협의하고, 상대 검토가 없으면 합의로 표시하지 않는다.

ChatGPT도 위 문장을 명시 수용한다. 5분봉/30분 교체를 불가능하거나 무조건 손해라고 판단한 것이 아니며, 현행보다 수익이 높다는 증거도 아직 없다.

## 바뀌는 점과 주요 위험

| 항목 | 현재 | 요청안 및 평가 |
|---|---|---|
| 판단 봉 | 15분 | 5분. 관측 횟수 증가, 짧은 변동과 순위 변화에 반응할 가능성 증가 |
| 자동 주문안 생성 | 약60분 | 약30분. 정상24시간 기준 기회24→48회지만 실제 거래 수가 두 배인 것은 아님 |

| 손절/추적 관측 | 목표30초 / 확정1분봉 | 이번 요청만으로 이 점검 간격을 바꾸지 않음 |

1. **잦은 교체와 비용:** 유지5위/탐색8위 정책은 같은 주문안의 매도·재매수 차단 이후에도, 새로 산6~8위 자산을 다음 판단에서 다시 정리할 가능성이 있다. 30분 교체에서는 이 기회가 늘 수 있다. 실제 재진입 대기2/6시간 등은 유지되므로 거래 횟수·회전율로 확인해야 한다.
2. **신호/실행 불일치:** tf5는 최신 신호 판단 경계가5분마다 바뀐다. 동기 API 수집·매도 처리·매수 전 재검사 중 경계를 넘으면 매수 거부가 생길 수 있다. 매도 후 매수가 거부되어 현금으로 남는 비대칭도 측정해야 한다. shadow와 live의 tf를 다르게 읽으면 출처검사에서 거부된다.
3. **비교 도구 자체의 불일치:** 현재 그림자 장부는 판단봉마다 거래를 평가한다. tf5에서는 하루최대288회 판단 기회인 반면 요청한 실거래형 주문안은48회 기회다. ATR 손절 경로도 다르다. 기존 그림자 결과를 바로5분/30분 실거래 성과라고 사용하면 안 된다.
4. **API와 스케줄:** 주문안3600초는 코드 상수여서 설정의 tf만 바꿔서는30분이 되지 않는다. 캔들조회는 더 자주 필요하고 API 그룹 한도는 같은 IP에서 공유된다. 호출 증가가 곧 제한 초과라는 뜻은 아니다. 시작 시각에 따라 밀리는 현재 스케줄과 재시작 직후 생성도 있어, 향후30분안은 고정 슬롯·중복 방지를 명시해야 한다.
5. **봉 누락과 시간 길이:** 거래 없는 구간은 봉이 없으므로72개 봉이 항상정확6/18시간인 것은 아니다. 시각 기준을 검사하고 누락을 수익0으로 채우지 않는다.

## 비용 예시와 기술 검사

교체 노출10만원에서 매도+매수 합산 비용을0.24%로 가정하면약240원,0.50%로 가정하면약500원이다. 이는 비교용 가정이지 현재계좌의 확정비용이나 실제비용 범위가 아니다.0.50%는 모의 설정(편도 가격비용0.2%+수수료0.05%)의 왕복 근사다. 실제체결·호가·수수료로 다시 측정해야 한다.

독립 합성 자료를 현재 rank 함수에 넣었을 때 L216/완료200봉은 후보0개, L216/완료217봉은 후보1개였다. 이는 데이터 길이 제약의 기술 재현이며 수익성 검사가 아니다. API가 최대200개를 주고 진행 봉이 포함되면 제외되므로 통상199~200개 완료봉만 남는다. 페이지 조회나15분 순위와5분 진입 분리가 선행돼야 한다.

과열 상한15%의 효과는 짧은 창에서 무조건 강하거나 약해진다고 단정할 수 없다. 18시간전100·6시간전120·현재125라면18시간은25%로차단,6시간은4.17%로통과한다. 반대로18시간전100·6시간전80·현재105라면18시간은5%로통과,6시간은31.25%로차단한다. 같은 수치도 거르는 종목이 달라진다.

## 1. 주요 위험 순위

1. **신호 의미가 바뀝니다.** L72가 18시간에서 6시간으로 줄어 다른 전략이 됩니다(동의). 과열 상한 15%도 효과가 달라지는데, 방향은 **약화**입니다. 6시간 안에 15% 오르는 경우는 18시간보다 드물어서 걸러지는 종목이 줄어듭니다. `require_positive_rs`도 짧은 기간의 잡음에 쉽게 통과합니다.
2. **18시간을 보존할 수 없습니다(동의, 보강).** `completed_candles`는 마감 안 된 봉을 빼므로 실제로는 최대 199봉이고, `len > L` 조건 때문에 L은 198 이하만 쓸 수 있습니다. L216으로 바꾸면 순위가 비어 주문안이 나오지 않습니다. 안전하게 멈추는 쪽이지만 오류 표시 없이 거래가 0건이 됩니다.
3. **재진입이 쉬워집니다(누락 보강).** `buy_block`의 눌림 판정은 `p.tf` ATR을 씁니다. 5분 ATR은 15분 ATR보다 작으므로 "1ATR 눌림" 조건이 더 쉽게 충족됩니다. 결과적으로 수익 청산 뒤 2시간이 지나면 다시 사기 쉬워집니다. 실거래에 직접 영향을 주는 변화입니다.
4. **그림자 비교가 실거래를 대표하지 못합니다(새로 지적).**
   - 그림자 장부는 `decide`가 봉마다 매매하므로 5분봉이면 하루 288회 회전합니다. 실거래는 30분 주문안으로 하루 48회입니다.
   - 그림자 손절은 판단봉(`p.tf`) ATR을 쓰고, 실거래는 `stop_tf=240` ATR을 씁니다. 5분 ATR이면 그림자 쪽 손절만 훨씬 좁아집니다.
   - 그대로 비교하면 신호 효과와 손절·회전 효과가 섞여 결론을 낼 수 없습니다.
5. **신선도 거부와 부분 실행이 늘어납니다.** 신호 유효 창이 900초에서 300초로 줄어듭니다. 매수는 `buy_block`과 `_trade`에서 여러 번 재검증하므로 경계를 넘을 확률이 커집니다. 그러면 "매도는 체결, 매수는 거부되어 현금만 남는" 비대칭 결과가 늘 수 있습니다.
6. **운영 정합성 문제가 있습니다.**
   - 주문안 주기 3600초는 하드코딩이라 설정만으로는 30분이 되지 않습니다.
   - shadow와 live 중 한쪽만 tf를 바꿔 재시작하면 주문안이 전부 거부됩니다.
   - 그리드 라벨("15분봉 기준 8·18·42시간")과 보고서 문구가 틀린 의미를 표시하게 됩니다.

## 2. ChatGPT 과장·누락 교정

- **비용 예시(수정):** 왕복 0.24%는 코드 자신의 가정보다 낙관적입니다. 알트코인은 편도 수수료 0.05%에 가격 비용 0.2%로, 교체 10만원당 약 500원입니다. 실제 체결값으로 다시 평가해야 합니다.
- **API 부하(보강):** 단정하지 않는 태도에 동의합니다. 다만 shadow와 live가 같은 IP의 캔들 한도(초당 10회)를 공유한다는 점이 빠졌습니다. `_get`은 429 오류를 2번까지만 재시도하므로 판단 실패가 늘 수 있습니다. 이것도 멈추는 방향의 실패입니다.
- **장점(동의, 축소 해석):** 대기 시간 단축의 대부분은 주문안 주기(60분→30분) 덕분입니다. 봉 길이(15분→5분)로 얻는 단축은 평균 5분 정도로 작습니다.
