# 사용자 의견에 따른 매도 후 매수 봇 개선 요청

## 사용자 원문

> 서로 현재 상황을 토의 해서 매도 종목 분량을 정하고 실행해서 매수할 종목의 종류와 금액을 결정하는 단계까지 봇을 개선시켜봐 내 의견이라고 말해줘

이 요청은 사용자의 의견이다. ChatGPT나 Claude가 먼저 제안해 합의한 내용으로 표시하지 않는다.

## 구현할 흐름

1. 현재 실제 잔고, 가용 수량, 잠금, 미체결, 최근 체결, 시각이 있는 호가를 읽어 일치 여부를 확인한다. 과거 스냅샷으로 주문 수량을 확정하지 않는다.
2. 기존 보유에 한정하지 않고 전체 후보를 비교한다. 현재 보유 유지와 일부 매도·교체의 비용과 위험을 비교해 매도 대상·수량·예상 대금·판단 근거를 작성한다. 새로 살 종목이 없는데 매도부터 강제하지 않는다.
3. 매도 주문 의도, 식별자, 허용 수량과 가격 범위를 영속 저장한다. 전송 결과가 불명확하면 조회로 확인하며 중복 매도를 하지 않는다.
4. 접수와 체결을 구분한다. 부분체결·미체결·거부·취소·통신 단절을 상태로 관리한다. 매도 예정액 전체를 매수 재원으로 사용하지 않는다.
5. 실제 체결 후 잔고와 수수료를 다시 대사한다. 확인된 가용 원화에서 다른 주문 예약과 비용 여유를 제외한 금액으로 매수할 종목·배분 금액을 다시 계산한다. 최초 예상과 달라지면 변경 사유를 기록한다.
6. 최소주문, 호가 단위, 수량 정밀도, 유동성, 데이터 지연, 전체 계좌·종목별 한도를 검사해 매수 주문안을 만든다. 매도 후 신규 후보가 악화되면 억지로 매수하지 않고 현금으로 남길 수 있다.
7. 사용자 문서에는 매도 결정과 체결 결과, 확보 원화, 매수 대상·금액·근거·진행 상태를 한 흐름으로 보여준다. 부분체결을 전량 성공으로 표시하지 않는다.

## 개발과 검토 분담

- Claude가 V5 구현 주담당, ChatGPT가 독립 검토와 오류 재현 담당이다. 같은 소스 파일을 동시에 수정하지 않는다.
- 기존 검토요청_ChatGPT.md의 평가 오류·재시도·현금 보존 문제를 먼저 해소한다. ALL의 가상 현금을 실제 계좌의 가용 원화로 취급하지 않는다.
- 실주문 계층은 전략 판단과 분리하고 기본 설정에서 비활성화한다. 현재 사용자 요청은 매매 흐름을 갖춘 봇 개선 지시이며, 이번 문서를 작성하면서 임의의 종목·수량 주문을 보내지는 않는다.
- 실제 활성화 전에는 구체적인 운용 범위와 최대 주문·계좌 위험 한도를 검토 가능한 설정으로 제시한다. 매 판단마다 사용자에게 기술값을 선택하라고 요구하지 않는다.
- 이전 답변의 신규3만원·특정 후보는 ChatGPT의 검토안이며 사용자 확정 조건이나 두 AI 합의로 사용하지 않는다.

## 완료 확인 기준

- 매도 일부만 체결되면 그 순대금만 다음 매수 예산에 반영된다.
- 매도 접수 여부 불명, 미체결, 거부 상태에서는 재원과 수량을 만들어 내지 않는다.
- 외부 주문이 잔고를 잠그거나 수동 거래가 발생하면 갱신·대사 후 계획을 재계산한다.
- 재시작 후 미확인 주문을 복구하며 같은 매도·매수를 중복 전송하지 않는다.
- 매도 후 신규 후보 소멸·호가 악화·자료 지연 시 매수를 보류하고 이유를 기록한다.
- 테스트는 주문 어댑터를 모사한다. 테스트와 검토 중 실계좌 주문은 전송하지 않는다.

Claude에게 위 원문을 사용자 의견으로 확인하고, 구현 순서와 변경 파일·검증 결과를 이 문서에 답해 달라고 요청한다.
