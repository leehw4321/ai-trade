수정 후 동의입니다. 제공된 코드와 점검 결과는 순위 계산의 타당성을 지지하지만, 수집·시간 계약까지 ‘검증 완료’로 부르기에는 부족합니다.
1. **동의—봉 경계:** 정렬된 T에서 대상은 `[T−96×BAR, T−BAR]`이며, 시작이 T−BAR인 봉은 포함하고 T인 봉은 제외합니다.
2. **수정요구—시간 표현:** `to_epoch`는 실제 UTC 에포크보다 9시간 큰 가상 눈금입니다. T도 같은 방식일 때만 안전하며, 실제 `timestamp()`와 혼용하면 시간 선택이 어긋납니다.
3. UTC aware datetime의 실제 에포크로 통일하고, 문서의 ‘분 단위’와 구현의 ‘초 단위’ 불일치를 수정하십시오.
4. T가 15분 경계가 아니면 조회 슬롯 전체가 빗나갑니다. 경계 외 입력을 거부하거나 내림하는 정책과 매개변수 범위를 명시해야 합니다.
5. **동의—누출 시험:** 미래 거래대금 변조 불변성과 경계 시험은 유효합니다. 다만 현재 목록·제외 목록의 역사적 적용과 당시 데이터 가용성까지 검증한 것은 아닙니다.
6. **수정요구—결측:** 90/96은 최대 6개 결측을 허용합니다. 합산에서는 빠진 값이 0과 같은 효과지만, 존재 개수 조건에서는 구별됩니다.
7. 무거래·수집 누락·거래정지를 현재 파일만으로 구별할 수 없습니다. 결측 사유와 수집 커버리지를 별도로 관리해야 합니다.
8. 상장 후 90봉만 있어도 편입되고, 최근 6봉이 없어도 적격일 수 있습니다. 최소 상장 기간·최신 거래 신선도·정지 상태 정책을 동결하십시오.
9. 스테이블 5종 제외는 명시적 연구 규칙으로는 가능하나, 역사적 분류를 재현하지는 않습니다. 제외 목록·적용 방식·생존 편향을 결과에 고정 기록해야 합니다.
10. **수집기 조건부 동의:** `to`가 UTC의 배타적 상한이라는 API 계약이면, 가장 오래된 봉 시작을 다음 상한으로 쓰는 페이지 연결은 맞습니다.
11. 다만 제공 자료만으로 API 계약은 확인되지 않습니다. 실제 응답으로 정확한 경계 포함 여부·정렬·페이지 간 중복과 누락을 검증해야 합니다.
12. `len(batch)<200`을 과거 끝으로 보는 가정도 확인이 필요합니다. 커서가 엄격히 감소하는지 검사하고, 404·빈 응답의 종료 사유를 기록하십시오.
13. 최신 이어받기는 기존 최신 봉을 다시 받아 갱신하고, 과거 확장도 기존 최저 시각 이전을 조회합니다. 그러나 기존 구간 내부의 누락·손상은 자동 복구하지 않습니다.
14. **필수 수정:** 진행 중인 봉도 저장됩니다. 공통 컷오프 C에 대해 `봉 시작+BAR≤C`만 분석하고, 기존에 저장된 미완성 봉은 재조회·갱신 여부를 확인하십시오.
15. 종목별 끝 시각 차이는 무거래와 수집 편차가 섞입니다. 실행 시작·종목별 요청 시각을 기록하고 공통 컷오프에서 적격 수·순위를 다시 산출해야 합니다.
16. **P0:** 시간 체계·T 경계·완성 봉·공통 컷오프를 수정하고, 원자료 형식·유한한 비음수 거래대금·격자·충돌 중복 검사를 추가하십시오.
17. **P1 시험:** 89/90/96봉, 마지막 6봉 결측, 동일 합계, 입력 순서 변경, UTC/KST 동일 순간, 잘못된 T·NaN 입력을 검증하십시오.
18. **P1 실제 데이터:** 표본 종목·기간을 독립 재수집해 값과 슬롯을 대조하고, 일괄 수집과 이어받기·과거 확장의 결과 일치 및 내부 누락 복구를 시험하십시오.
