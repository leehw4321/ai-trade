# Claude 리뷰: SAMEPLAN-v1 / ASKCAP-v1

전제: 저는 실제 코드, 원장, 테스트 결과를 보지 않았습니다. 아래 내용은 제시된 계약문만을 검토한 것입니다. 구현이 이 계약과 일치하는지, 그리고 수익성은 검증된 것이 아닙니다.

## 1. 계약별 입장

### SAMEPLAN-v1: 조건부 수락 (수정 1건 필수, 확인 2건)

**필수 수정: 충돌 시 "플랜 전체 거부"는 매도 보호를 막을 수 있습니다.**
- 현재 계약에서는 sell 집합과 buy 집합이 교집합을 가지면 매도까지 전부 실행되지 않습니다.
- 플랜 안의 매도가 순위 이탈 같은 전략성 매도뿐이고, 손절·트레일·부분익절이 플랜과 무관하게 receiver 측에서 독립적으로 돈다면 문제가 없습니다.
- 반대로 보호성 매도가 플랜을 통해서만 나간다면, 이 변경은 간접적인 청산 회귀입니다.
- ASKCAP 계약에는 "보호 매도를 억제하지 않는다"는 문구가 있습니다. SAMEPLAN의 전체 거부는 이 원칙과 일관되지 않습니다.
- 제안하는 형태는 다음과 같습니다. 충돌이 감지되면 해당 플랜의 매수 전부를 첫 API 호출 전에 폐기합니다. 매도는 기존 보유·소유권 검증을 통과한 것만 실행하고, 충돌 사실을 경보로 기록합니다.
- 오래된 generator를 신뢰할 수 없다는 논리는 매수에는 강하게 적용됩니다. 하지만 보유분을 줄이는 매도에는 그만큼 적용되지 않습니다.
- 대안도 있습니다. 보호 청산이 플랜과 완전히 독립적임을 코드와 테스트로 확인했다면, 현재의 전체 거부 계약을 그대로 수락할 수 있습니다. 둘 중 어느 쪽인지 명시해 주세요.

**확인 1: "원래 보유 종목 전부를 매수에서 제외"가 기존 동작과 같은지**
- 기존에 `keep` 종목이 이미 eligible에서 빠져 있었다면, 실질적으로 추가되는 변화는 "이번에 매도할 종목 제외"뿐입니다.
- 기존에 보유 종목 추가매수(물타기·불타기)가 가능했다면, 이 계약은 버그 수정이 아니라 전략 변경입니다. 이 경우 별도 합의가 필요합니다.

**확인 2: 빈 슬롯 대체 효과**
- 매도 종목을 제외하면 buy3가 다음 순위 종목, 예를 들어 6~8위로 채워질 수 있습니다.
- 이는 Finding 3(6~8위 매수 후 다음 사이클 매도)을 간접적으로 늘릴 수 있습니다.
- 이번 변경에서 정책을 바꾸지 말자는 데는 동의합니다. 다만 대체 매수가 발생했는지 로그에 남겨 이후 비교 연구의 입력으로 쓰도록 해 주세요.

**나머지 항목은 계약 그대로 수락합니다.**
- receiver의 사전 거부, 매수 직전 durable `last_sell` 재조회, 기존 쿨다운(익절 2h, 손절 6h, 만료 24h) 유지
- 익절 후 재진입 시 신선한 ATR과 실제 ask로 dip 요건 확인
- 수동·자동 경로 공통 적용

### ASKCAP-v1: 계약 그대로 수락 (구현 리뷰와 테스트 조건부)

정확한 계약을 수락합니다. 아래 사항은 완화가 아니라 해석을 명확히 하기 위한 요청입니다.

- **anchor 일관성**
  - `rs ≤ -1`이면 `anchor` 계산이 정의되지 않으므로 거부합니다.
  - 전달된 `anchor_close`와 `signal_close/(1+rs)`의 일치 여부는 직렬화 반올림을 감안한 tolerance로 검사합니다.
  - 이 tolerance는 일관성 판정에만 쓰고, 상한 비교에는 적용하지 않습니다.
- **신호 시점 rs도 재검사**: 신호 종가 기준 rs ≥ 현재 cap이면 ask를 보기 전에 거부합니다.
- **경계값**: `ask/anchor - 1 >= cap`이면 거부합니다. 정확히 cap과 같은 값도 거부입니다.
- **cap 설정 의미**
  - 기존 disabled 의미를 따르되, `0`, `None`, `NaN`, 음수가 각각 어떻게 해석되는지 명시하고 테스트합니다.
  - 특히 `NaN` cap이 비교 결과 False 때문에 "통과"로 처리되는 일이 없어야 합니다.
- **신뢰 경계**
  - receiver는 producer가 준 `signal_close`와 `anchor_close`를 신뢰하는 구조입니다.
  - 비용이 크지 않다면 해당 `signal_closed_at` 캔들의 종가를 거래소에서 직접 받아 대조하는 것을 권합니다.
  - 지금 넣지 않는다면, 이 신뢰 경계가 남아 있다는 점을 문서에 명시해 주세요.
- **고정 anchor의 의미**
  - 실행 시점에 18시간 창이 이동해 "현재 기준 anchor"가 달라질 수 있습니다.
  - 이번 계약은 "신호 캔들 기준 anchor 대비 실제 ask"를 제한하는 것으로 이해합니다. 이 의미를 문서화해 주세요.

**수동 경로 경계 질문에 대한 답**
- 수동 경로가 사람이 명시적으로 시작한 경우에만 호출된다면, 경계를 지금 조일 필요는 없습니다.
- 다만 다음 세 가지는 배포 전에 테스트로 고정해야 합니다.
  1. 자동 런타임, 스케줄러, 재시도 로직이 수동 execute 경로를 호출할 수 없어야 합니다.
  2. context 검증 실패가 수동 경로로 fallback되지 않아야 합니다. 이 내용은 계약에 이미 있으므로 테스트로 확인합니다.
  3. 주문 기록에 origin(auto/manual)이 남아, 수동으로 표시되었지만 실제로는 봇이 만든 주문이 있는지 감사할 수 있어야 합니다.
- 이 중 하나라도 보장되지 않으면, 수동 경로에도 ASKCAP를 요구하도록 경계를 조여야 합니다.

## 2. 누락된 엣지 케이스와 필요한 테스트

**SAMEPLAN 관련**
- **마켓 식별자 정규화**: `KRW-XRP`, `xrp`, `XRP`처럼 표기가 달라도 교집합이 정상적으로 감지되는지 확인합니다.
- **중복 항목**: buy 목록 안의 중복, sell 목록 안의 중복이 있을 때의 동작을 확인합니다.
- **플랜 간 경쟁**
  - 플랜 N이 X를 매도하고, 그 매도가 체결·기록되기 전에 생성된 플랜 N+1이 X를 매수하는 경우입니다.
  - `last_sell`이 체결 확정 시점에만 기록된다면 이 틈이 열립니다.
  - 요구사항: 미체결 매도 의도나 pending sell도 쿨다운 시작으로 간주합니다.
- **손익 분류가 불확실한 매도**
  - 체결가가 아직 없거나 부분체결이라 익절인지 손절인지 알 수 없는 경우입니다.
  - 새 임계값을 만들지 말고, 기존 규칙 중 더 엄격한 쪽(6h)을 적용합니다.
- **부분 매도의 처리**: 부분 익절이 `last_sell`을 갱신하는지, 그 경우 쿨다운 분류가 의도와 맞는지 확인합니다.
- **`last_sell` 저장소 이상**: 파일 손상, 누락, 파싱 실패 시 매수를 막는 fail-closed로 동작해야 합니다. 매도는 막지 않습니다.
- **시간 기준**: UTC와 KST 혼용, 2h/6h/24h 경계값 정확성, 시스템 시계 변경 시 동작을 확인합니다.
- **ATR 조회 실패**: 조회 실패나 캔들 부족 시 해당 매수를 skip합니다.
- **동시성**: receiver 두 개가 동시에 돌거나 같은 플랜이 재처리되는 경우를 다룹니다. 플랜 ID 기준 idempotency와 잠금이 필요합니다.
- **크래시 후 재시작**: 매도만 실행된 상태에서 재시작할 때, 같은 플랜의 매수가 재실행되지 않아야 합니다.
- **"보유"의 정의**: 계정 보유 기준인지 봇 소유 기준인지 명확히 합니다. 사용자가 수동으로 보유한 코인을 봇이 매수하지 않는다는 기존 소유권 규칙과 충돌하지 않는지 확인합니다.

**ASKCAP 관련**
- **ask 조회 실패 또는 비정상 값**: 실패, 빈 호가, `ask ≤ 0`, `NaN`이면 해당 매수를 skip합니다.
- **신선도 경계**: ATR 조회 도중 새 캔들이 마감된 경우, 재검사 지점에서 stale로 판정되어야 합니다.
- **시계 오차**: 거래소 시각과 로컬 시각이 어긋날 때의 동작을 정의합니다.
- **context 불일치**: 다른 마켓의 context, 누락된 context, sell 항목에 붙은 불필요한 context를 처리하는 방식을 확인합니다.
- **outer 메타데이터 문제**: outer source 메타데이터가 없거나 timeframe이 다르면 자동 매수 전체를 skip합니다.
- **검사 순서**: 일일 손실 halt 검사가 ASKCAP보다 먼저 실행되어야 합니다. halt 상태에서 불필요한 API 호출이 없어야 합니다.
- **감사 기록**: 결정 기록에 ask, anchor, cap, rs, 거부 사유가 남는지 확인합니다.

**간접적인 보호·청산 회귀 점검 (가장 중요)**
- **예외 격리**: 새 검증 코드에서 예외가 나도 receiver 루프가 죽거나, 같은 사이클과 다음 사이클의 매도, 손절, 트레일 처리가 건너뛰어지면 안 됩니다. 마켓 단위 예외 격리 테스트가 필요합니다.
- **매도 단독 실행**: 매수가 전부 거부된 플랜에서도 매도는 기존과 동일하게 실행되어야 합니다. SAMEPLAN 수정안을 채택한 경우에 해당합니다.
- **기존 동작 불변**: 손절, 트레일, 부분익절, 일일 halt, 소유권 검증의 기존 테스트가 무변경으로 통과해야 합니다.
- **사고 재현 테스트**: 원장에 있는 두 번의 "매도 2초 후 재매수" 플랜 입력을 offline으로 재생했을 때, 첫 API 호출 전에 차단되어야 합니다.
- **cap 사고 재현**: anchor 100, 신호 110, ask 120 사례를 재현해 거부되어야 합니다.
- **전체 테스트**: V5 전체 스위트를 통과해야 하며, 실패가 있으면 결과를 그대로 보고합니다.

**배포 시 주의**
- 현재 매수가 halt 상태이므로, 배포 후에도 실거래 매수 경로는 실제로 실행되지 않습니다.
- 매수를 재개하지 않는 범위에서, generator가 만든 플랜에 대한 판정을 shadow 로그로만 남기면 halt 해제 전에 판정 로직을 관찰할 수 있습니다.

## 3. 버그 수정과 향후 전략 연구의 분리

**이번 변경 (버그 수정 및 기존 규칙 집행)**
- 같은 플랜 안에서의 매도 후 재매수 차단
- 쿨다운과 dip 규칙을 실행 시점의 최신 상태로 집행
- 기존 18h 15% 상한을 실제 ask 기준으로 집행

이 변경은 수익 개선을 주장하지 않습니다. 반복 손실 구조 중 규칙 위반으로 생긴 부분만 막습니다.

**별도 연구 과제 (이번 변경에 포함하지 않으며, 임계값은 제안하지 않음)**
1. **단기 진입 타이밍**: 장기 순위가 단기 상승 모멘텀을 뜻하지 않는다는 문제입니다. 진입 시점과 그 이후 단기 수익률 분포를 원장에서 비교하는 것부터 시작합니다.
2. **시장 국면 필터**: 하락장과 횡보장에서 손실이 집중되는지 확인하는 사후 분석입니다.
3. **순위 정책 불일치(top8 / M5 / buy3)**: 6~8위 매수 후 즉시 이탈하는 빈도와 손익을 독립적으로 비교합니다. 이번 변경으로 늘어날 수 있는 대체 매수 로그를 입력으로 씁니다.
4. **시세 장애 시 보호**: 보유 포지션 시세가 끊겼을 때의 청산 정책입니다. 현재는 장애 기록까지만 되어 있습니다.

각 과제는 out-of-sample 검증과 사용자 합의를 거친 뒤에만 설정이나 정책 변경으로 넘어가야 합니다. 이번 PR에서 다루면 안 됩니다.

**요약**
- ASKCAP-v1은 정확한 계약대로 수락합니다.
- SAMEPLAN-v1은 둘 중 하나가 충족되면 수락합니다.
  - (a) 충돌 시 매수만 폐기하고 검증된 매도는 실행하도록 수정한다.
  - (b) 보호 청산이 플랜과 독립적임을 테스트로 입증한다.
- 두 계약 모두 최종 수락은 구현 리뷰와 전체 스위트 결과를 확인한 뒤에 합니다.
