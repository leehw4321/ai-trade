# 설계 검토 의견 (코드 미검토, 승인 해시 없음)

**결론: 조건부 동의.** 아래 필수 수정을 반영한 뒤 코드 단계로 넘어가는 데 동의합니다.

## 동의
- 신규 매수 rank≤M을 생성부와 수신부 양쪽에서 검증하는 구조
- 플래그 기본값 False, 신호 ID를 전송 전 claim, 과거 신호 catch-up 금지
- 미확정 주문은 기존 identifier로만 대사
- 손절과 이익보호는 경계 대기 없이 즉시 처리, 유예 대상에서 제외
- 4.5% 손절, 재진입 규칙, 국면 필터 유지
- 미검증 설정(15분 발행, M7, 유지7)은 연구 후보로 분리

## 필수 수정
1. **entry_scan 8→5는 현재 운영값의 변경입니다.** "합의 유지"가 아니라 변경으로 명시하고 근거를 기록해야 합니다.
2. **기존 순환 경로를 비활성화해야 합니다.** rotation_enabled=True일 때 기존 경로가 꺼지는지 코드와 테스트로 증명해 주세요. 두 경로가 동시에 매도하면 안 됩니다.
3. **신호 ID 생성 규칙을 정해야 합니다.** 시간 슬롯(UTC 기준) + 심볼 + 방향 + 설정해시로 결정적으로 만들어 주세요. claim 후 전송 전에 죽으면 신호가 유실됩니다. 이 경우 "유실 허용, 재발행 금지"로 하고 기록을 남기는 정책을 문서화해 주세요.
4. **중단 기준과 롤백 절차를 미리 정해야 합니다.** 예를 들어 순환 손실이 N회 또는 X원에 도달하면 플래그를 False로 바꾸고 재시작합니다. 이 절차를 사전에 합의해 두어야 합니다.
5. **로깅은 실패해도 주문 경로를 막으면 안 됩니다.** 로그에 키나 계정 식별자가 없어야 하고, 디스크 증가 상한도 필요합니다.

## 놓친 위험
- **근거가 약합니다.** 1승4패, −5893원은 모의 장부 5건뿐입니다. "순환에서 손실"이라는 근거로 새 순환을 실거래에 켜는 것은 개선 가설일 뿐 입증이 아닙니다. 보고서에 그렇게 표기해 주세요.
- **국면 필터 72시간 만료 동작이 정의되지 않았습니다.** 운영 중 만료될 때의 동작을 정해야 하고, 새 경로가 만료를 연장하거나 우회하지 않아야 합니다.
- **시각 기준을 통일해야 합니다.** 서버와 거래소 시계가 어긋나면 완료봉 판정이 틀어질 수 있습니다. 거래소 봉 시각을 기준으로 해 주세요.
- **재시작 전에 BOT_DISABLED를 확인해야 합니다.** 대화 시작 시점 git status에 저장소 루트의 `BOT_DISABLED`가 미추적 파일로 보였습니다. 의도된 정지 신호인지 확인하고, 재시작 절차가 이를 존중하는지 검증해 주세요.
- **SHA 승인 범위를 넓혀야 합니다.** 코드뿐 아니라 설정 패치 diff도 포함한 묶음 전체에 대해 승인해야 합니다.

정확한 코드와 해시를 받으면 별도로 검토하겠습니다. 현재 단계에서는 승인 해시도, 배포 완료도 없습니다.
